# 功能与回归验收矩阵

PASS 必须有命令、断言/人工操作记录、平台/架构和日志。NOT RUN/BLOCKED 不能当 PASS。此矩阵是最低要求，T00 可补充样例。

平台简称 W64/WA64、M64/MA64、L64/LA64 对应 Windows/macOS/Linux 的 x64/ARM64。全部六种目标需要原生归档核心执行证据；GUI/系统集成须按适用平台运行，跨编译与仿真结果分别标注。无法取得对应环境时该平台不具备“已验收”结论。

## 尚不纳入首版完成承诺

Bandizip 专业版的密码恢复、复杂损坏修复、病毒扫描、SFX 生成，以及没有调查过的专有格式，不是通过换用 7-Zip 就自动获得。首轮原生版必须列成明确未支持项。不要展示可点击的假实现。

原生第一版包含已有功能修复和 R31 等日常操作缺口；密码管理器、完整自动更新客户端、图库预览和所有系统的全部扩展菜单可后续单列任务。T07 必须定义各平台实际支持的菜单级别，T10 报告中不得把“经典菜单可用”写成“Win11 现代菜单已完成”。

## 样本管理

测试样本放 native/tests/fixtures 或由生成器创建，记录来源、许可、生成命令和 SHA-256。不要提交个人压缩包、真实密码或 Bandizip 专有程序。高危路径样本只在隔离临时目录测试，所有越界目标都是测试自建路径。大文件测试在定时/手动 CI 中运行，PR 测试保留轻量代表样本。
