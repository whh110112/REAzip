# T10：独立验收、问题收口与发布准备

## 依赖 / 范围

依赖 T00–T09 的交接单与候选包。宜由未编写主要实现的 Sol 聊天执行独立复核，但不要求并发代理。只读验收优先；发现缺陷可小范围修复或派回明确负责人，改后重跑受影响检查。

## 实施

1. 获取实际候选源码 SHA 与 artifacts，验证哈希和版本，不只检查开发目录里的 exe。
2. 对照 feature-parity.md、T00 设计基线及全部 R01–R35 检查，不把 stub、未运行、靠仿真执行的目标写成原生通过。
3. 六目标的核心归档测试必须实际执行；每平台 GUI 完成主要成功/失败/取消流，系统集成在隔离环境验收。报告明确架构和运行环境。
4. 重点复查历史问题：错引擎架构、库权限、POSIX路径、缺密码阻塞、选中覆盖、AES标签、TGZ两层、关联打开、并发取消、便携数据。
5. 截图对比现有设计和 6 皮肤；检查 18 语言与可访问性；基准测量说明两版版本、相同场景、设备和统计方式。旧版某平台无法启动时如实记录，不能伪造启动改善百分比。
6. 独立检查只读归档、损坏包、路径逃逸和符号链接、磁盘满、同包并发、临时文件、密码日志、取消保存。安全检查不以一条自动扫描零告警代替行为验证。
7. 更新 README 和差距文档，定位写为“参考 Bandizip 行为、使用 7-Zip 的原生跨平台实现”，不用“已完整逆向 Bandizip 内核”等无法证实的描述。
8. 写原生版本发布说明与安装指南，列出支持架构、Windows 安装 EXE/便携 ZIP、macOS签名状态、Linux发行形式、旧设置迁移和未支持项。
9. 默认只准备草稿和待发布清单，不移动旧标签，不删除 v0.2.x；用户明确授权公开时，才用通过验收的单一 SHA/版本发布并核对附件完整性。

## 完成门槛

- 所有必须功能和历史高优先级问题无 FAIL；所有目标的执行证据完备。任何 NOT RUN/BLOCKED 都明确阻止相应“已支持”宣称。
- 修复后复验通过，且没有为通过测试而删掉验收标准或缺陷样本。
- 包体积降低有实际数据，视觉保留有实际截图，原生引擎接入有 identity/依赖检查，全部独立可查。
- 若仍有发布阻塞，提交具体阻塞清单和已经完成的有效产物，不以“全部完成”结案。
