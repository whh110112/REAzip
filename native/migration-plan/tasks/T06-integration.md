# T06：完整操作串联与功能补齐

## 依赖 / 范围

依赖 T02/T03/T04/T05/T08；平台入口依赖 T07 的接口并在交付前接实实现。负责 native/app、native/models、tests/integration；UI 需要小改时与 T05 负责人同步。

## 实施

1. 将打开、列表、目录、标签、搜索、排序、选择、压缩、解压、添加、删除、重命名、完整性测试接到真实 worker。
2. 将密码、错误、进度、取消和覆盖挑战完整接线。取消弹窗即取消任务；选中提取也必须询问；按钮忙碌状态与任务生命周期一致。
3. 系统选择目录/文件返回原生路径，C++ 统一处理路径。不能复制旧 renderer 的反斜杠拼接函数。
4. 对只读格式禁用修改；格式不支持的密码/分卷选项清楚禁用。压缩后删源必须有明确确认与结果反馈。
5. 多卷创建完成后打开真实首卷或显示结果清单，不能尝试打开未生成的未分卷文件名。
6. 包内文件双击：选中项临时解压后用系统打开；可执行脚本/程序单独提示，不因双击任意条目自动执行不可信程序。临时目录有生命周期和启动清理。
7. 拖放打开真实归档；拖出所选文件通过 T07 平台适配，只导出用户选择的条目。平台暂不可用时列入明确缺项，不能使用空拖放事件冒充实现。
8. 正确恢复标签，不持久化密码；失效路径可提示移除。全包搜索与当前目录过滤的范围需在 UI 表明。
9. 数据变更后刷新 entryId 和列表，保留合理导航状态；不得继续使用旧索引删除另一条目。
10. 核对旧版有效功能迁移完成，删除生产入口中的所有 mock。引擎返回未知信息时显示未知，不能显示 AES 或“成功”等推测值。

## 验收

R03/R05–R13/R17/R19/R23–R26/R31/R32/R35。至少用真实 GUI 走完：打开密码包→错误密码→正确密码→选中解压遇到同名文件→跳过/改名→取消→再次操作；以及压缩→测试→修改→独立工具校验。

不能只跑底层单元测试，必须有跨层失败流和多任务切换证据。记录界面是否响应、最终文件内容和任务状态。
