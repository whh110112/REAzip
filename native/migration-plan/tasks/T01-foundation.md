# T01：原生工程、依赖锁定与六目标可行性验证

## 依赖与目标

依赖 T00。建立可复现构建，并先证明完整 7-Zip 原生库在目标平台/架构可用。此任务是整个迁移的技术门槛。

## 修改范围

native/CMakeLists.txt、CMakePresets.json、cmake/、include/reazip/、bootstrap/、deps.lock.json、tests/foundation、依赖/平台文档。预留 engine/read、engine/write、worker、jobs、ui、app、models、platform、settings、i18n、themes 子项目挂载点。后续任务通过子目录扩展，不抢根文件。

## 实施

1. C++17、Qt6 Core/Gui/Qml/Quick/QuickControls2；仅用实际需要模块，动态部署 Qt。精确锁定可获取的稳定开源 Qt 小版本、工具链和各系统最低版本，说明选择依据。
2. 验证 bit7z 4.1.0 与完整 7-Zip 26.04 的兼容性；必要版本调整要记录原因与实测，不默认最新主分支可用。动态库须由官方可信二进制或锁定官方源构建获得。
3. 明确 Windows 7z.dll、Linux/macOS 对应共享库的实际构建目标、名称和导出接口；不要把 7zz 可执行文件改名成共享库，也不要用仅 7z 格式的精简库冒充完整引擎。
4. 建六目标依赖清单，校验机器类型、运行库/ABI、库加载路径。只从受控应用目录加载。缺库/错架构报清楚错误，不从 PATH 加载随机库。
5. 从 T00 契约建立公共类型、引擎抽象、平台服务接口、设置/主题接口。提供 dummy 实现供并行任务编译，但 dummy 不可进入最终发布。
6. 最小 headless 程序能查询 identity、列出/解压小 ZIP 和 7z；至少一个需完整库支持的格式验证，例如 RAR5 合法样本。
7. 最小 Qt Quick 窗口能离线启动。Qt、bit7z、7-Zip 都不依赖最终用户安装 SDK。
8. 记录许可证文件与源代码获取方式，选择可分发的模块组合；静态 Qt 不作为默认方案。

## 验收

R01：六目标分别有配置/编译/装载/真实归档操作状态；本机无法运行的目标用相应 CI/机器验证，不把交叉编译当执行证据。版本/哈希/工具链完整可追溯。

能够给下游提供统一公共头、可运行最小样例和不冲突的目录边界。六目标工具链/库无法解决时准确记录技术阻塞，不让 UI 大规模开发掩盖引擎问题。
