# T03：解压、压缩和归档修改的正确性

## 依赖 / 范围

依赖 T02。负责 native/engine/write、tests/engine-write。业务规则按公共契约；不改 UI 或任务协议。

## 实施

1. 全包/选中项/目录解压按条目 ID 操作，不把文件名当通配符。ask、overwrite、skip、rename 对全部情况一致。
2. 路径和链接校验：禁止写出目标目录，处理大小写碰撞、Windows 设备名、重解析点、符号链接和竞争条件；记录跳过/拒绝项，避免静默成功。
3. ZIP/7Z/TAR/TAR.GZ 创建与更新；显式输入路径映射，避免写入绝对目录和不必要的用户目录。TAR.GZ 使用原生库两阶段流或临时文件，支持完整两层展开，不调用 tar.exe。
4. ZIP AES-256、读取 ZipCrypto、7z 密码和可选文件头加密；参数无效或格式不支持时拒绝，绝不静默降级。
5. 压缩级别、分卷、自定义分卷尺寸、中文路径。准确解析尺寸并防溢出；缺卷/错误卷输出可解释错误。
6. 包内添加、删除和重命名走同一事务式更新；修改加密包保留必要密码策略，不能把新加文件意外变成明文。
7. 新建/修改先暂存并验证后提交；处理磁盘满、权限失败、取消、输出存在。大文件用流，不将整个包读进内存。分卷作为文件集合提交/回滚。
8. 压缩后删源必须等输出提交、验证且源文件未发生预期外变化；失败、取消、漏文件、警告情况下保留源文件。删除策略与 UI 明示对应。
9. 进度、密码、覆盖、取消统一使用回调接口；不得在引擎内弹 UI。按能力查询禁用不支持的修改。

## 验收

R02/R03/R06–R17/R34/R35。必须包含现有 bug 回归：选中项询问覆盖、TGZ 最终文件哈希、ZIP AES 元数据、取消不损坏原包、删源失败保护。

测试覆盖每个已支持目标架构的代表操作；重型 >4 GiB/多卷测试可单独 CI，但给出执行证据。危险路径测试只针对测试自建沙盒。
