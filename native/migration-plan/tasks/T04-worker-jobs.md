# T04：worker、任务队列、交互挑战与取消

## 依赖 / 范围

依赖 T01 公共类型；可以用可控假引擎与 T02/T03 并行，真实引擎集成后重跑测试。负责 native/worker、native/jobs、tests/jobs。

## 实施

1. 创建 C++ worker 可执行程序与 GUI 侧 JobController。用 Qt QProcess 私有管道启动，禁止 shell，禁止依赖 7z CLI。
2. 实现 CONTRACTS 的版本化协议、分块列表、消息上限、序列号、精确 64 位数值和异常断流处理。诊断只走 stderr。
3. 一个任务一个进程，初始串行重任务；实现同归档读写锁和跨进程异常恢复，避免全局 currentProc。
4. 工作线程可阻塞在归档库，但控制线程持续处理 cancel 与 respondChallenge；密码/冲突事件绑定 jobId/challengeId。
5. 用户关闭密码或覆盖弹窗时取消相应任务；过期答复不作用于新挑战，错误密码可重复输入，不能无限等待不可见 UI。
6. 取消先请求库停止，再按明确超时终止该 worker。清理和事务回滚与 T03 协作；GUI 不冻结、不误杀其他任务。
7. 首版 worker 进程隔离不宣称操作系统沙箱；基础 DLL 搜索路径、进程启动参数、异常退出处理要受控。
8. 测试密码不进 argv、设置或日志；日志不打印完整 JobRequest。限制恢复材料中的私人路径和归档文件名。

## 验收

R05/R07/R08/R14/R15/R18/R33。覆盖半行 JSON、超长消息、错版本、重复终态、worker 崩溃、密码框期间取消、两个任务快速切换。

UI 侧测试用同一事件接口，不能测试时绕过 JobController。真实引擎接上之后验证加密包等待不会阻塞取消信号。
