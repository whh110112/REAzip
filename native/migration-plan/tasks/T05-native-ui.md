# T05：按现有设计重建 Qt Quick 界面

## 依赖 / 范围

依赖 T00/T01。负责 native/ui、UI 组件与 tests/ui，使用统一模型接口及 token。T08 提供主题/语言数据前可用同接口占位，但要标注 mock。

## 设计原则

保留原有信息结构和视觉辨识度：顶部品牌/标题、多标签、胶囊按钮工具栏、面包屑、文件表格、右侧详情、底部状态栏、同风格弹窗。原生迁移不是重新设计成默认 Qt 示例应用。

## 实施

1. 将 T00 的颜色、尺寸、字体、圆角、边框、阴影映射到 QML token 和可复用组件。逐一对照现有截图。
2. 实现空状态、主窗口、多标签、压缩/解压、密码、冲突、进度取消、设置/语言/皮肤界面，以及未支持功能的明确禁用状态。
3. 使用虚拟化表格与列表，键盘焦点、选择/多选、可排序列、鼠标/键盘导航都可用。核心逻辑放 C++ 模型，QML 不做归档解析。
4. DPI 适配、窗口缩放、长文件名、18 语言长文本、RTL、系统字体差异和高对比度要考虑；用 Accessible 属性提供可读名称。
5. 标题栏和系统窗口控制尽量遵循平台；无法实现的 Mica/模糊采用颜色降级，仍保留主题布局。不得全局关闭渲染/安全功能掩盖平台问题。
6. UI 发语义动作，不直接写文件、拼路径或启动命令。密码/冲突 UI 接 T04 模型；接线由 T06 完成。
7. 自定义主题只绑定白名单属性，不接受任意 QML/JS/CSS 执行。

## 验收

R23/R24/R25/R26 的 UI 部分。对 T00 基准场景生成并排截图或差异图，逐项解释系统控件差异。布局/色值/功能入口没有未经说明的改变；核心操作按钮不能因翻译或最小窗口尺寸被遮挡。

记录可量化设计偏差，例如 100% DPI 下主要区域尺寸是否与基线保持在约 2 个逻辑像素内；字体抗锯齿按平台单列，不把像素 diff 零差异作为不现实门槛。
