# T00：行为、视觉基线与公共契约确认

## 任务目的

把“保留当前设计、修复问题”转成可验证的规格，防止后续只做出另一套压缩软件界面。

## 输入与依赖

无前置实现。先读上级总览、规则、契约、回归矩阵和 REFERENCE-audit.md。项目基线及路径见总览；检查 Workbuddy 新改动。

## 工作内容

1. 清点 renderer/index.html、styles.css、skins.js、locales-*.js、design-spec.html、shots-*.png 和实际启动界面，区分已有实现、占位、错误行为。
2. 固定视觉场景：空窗口、多标签归档、目录与选中项、压缩、解压、冲突、密码、进度/取消、设置、6 皮肤、中文/英文/RTL。主窗口 1120×740、最小窗口、125%/150%/200% DPI 分别记录。
3. 抽取 token、尺寸、字体回退、圆角、间距、表格列、导航与快捷键；生成组件和状态清单，不重新设计外观。
4. 将审查缺陷映射到回归 Case ID；明确智能解压、添加到当前目录、重复条目、编码、加密和覆盖的期望规则。参考 Bandizip 的行为时注明观察过程；没有证据的不写成已逆向还原。
5. 确认公共契约字段/状态，输出可评审 schema 草案和界面模型接口草案。无需开始写全套 C++ 业务。

## 产物与所有权

native/docs/design-baseline.md、feature-parity.md、behavior-spec.md、ui-components.md、contracts-v1.md；native/design/tokens.json、基准截图清单及证据目录。公开截图检查用户路径和私人文件名。任务交接单 native/docs/handoffs/T00.md。

## 验收

- 每个现有主要按钮有操作、成功/失败/取消行为和新模块负责人。
- 6 皮肤与 18 语言有迁移覆盖表；明确自定义 CSS 的不兼容范围。
- “当前错误行为”没有被当成必须保留的兼容要求。
- T01 能据契约建立编译接口，T05 能据截图和 token 复刻界面。

## 不做

不删旧应用、不换品牌、不做完整原生实现、不发版。T00 不以再安装一套逆向工具作为开工的必然前提。
